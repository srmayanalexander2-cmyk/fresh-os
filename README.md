# FreshOS 2 · Stratus

A clean-slate native x86 system. Stratus is a new kernel and desktop, not a skin on FreshOS 1.x, Linux or a web page. The bounded x86 interpreter is adapted from 1.5; the kernel remains native. The [1.5 release](https://github.com/srmayanalexander2-cmyk/fresh-os/releases/tag/v1.5.0) remains available for older software. **Home disks are not interchangeable.** This is a development release, not a feature-compatible upgrade.

[Preview 4 downloads: ISOs, VM bundles and checksums](https://github.com/srmayanalexander2-cmyk/fresh-os/releases/tag/v2.0.0-preview.4) · [Test results and guest screenshots](docs/verification.md)

**Preview 4 bundles:** [Normal](distros/FreshOS-Normal.zip) · [Lite](distros/FreshOS-Lite.zip) · [VMware](distros/FreshOS-VMware.zip) · [VMware Lite](distros/FreshOS-VMware-Lite.zip). These builds include a guided first-run screen, clickable desktop app hub, built-in sample files, right-click menus, Media, Photos, Snake, [IMP2 packages](docs/imp.md) and [native x64 processes](docs/native-processes.md). ## Boot a VM

Extract one ZIP. Boot its ISO as an **optical disc**. BIOS runs the 32-bit kernel; x64 UEFI runs the 64-bit kernel (disable Secure Boot). VMware packages include a VMX: extract the whole ZIP to a writable directory, then open **`FreshOS-x64.vmx` for native x64 applications** or `FreshOS.vmx` for legacy BIOS. The two profiles share one disk: never run them simultaneously. **To install:** open System → Install to Home disk → Confirm Install, or type `install` in Terminal and press **I** on the System confirmation page. Wait for “Install verified”, shut down the VM, detach the CD and boot the disk. Before installation, `Home.img` is only a data disk. Do not attach irreplaceable data or physical disks.

| Edition | Display selection | VM package |
|---|---|---|
| Normal | Largest suitable 32-bit framebuffer up to 1600×900 | ISO + marked Home disk |
| Lite | Up to 1024×768; smaller sky texture and framebuffer allocation | ISO + marked Home disk |
| VMware | Normal renderer | BIOS VMX + flat IDE VMDK descriptor and extent |
| VMware-Lite | Lite renderer | 32 MiB BIOS VMX + flat IDE VMDK descriptor and extent |

Example: `qemu-system-x86_64 -m 96 -cdrom FreshOS-Normal.iso -drive file=Home.img,format=raw,if=ide,index=0 -boot d`. Without the data disk, the desktop works in memory; documents disappear after power-off.

**Try an actual Windows program:** On x64 UEFI with the included Home disk, press F3, enter `install cal64`, then `run cal64 2 2024`. This is a third-party PE executable, not a built-in calendar command.

## Use the desktop

* First run offers **Try live**, **Customize**, and **Install**, plus clickable Files/Media/Photos samples. Customize opens a setup screen for accent, wallpaper, taskbar position, auto-hide and new-window behavior before choosing a live session or installation; full Settings has the remaining options. The desktop hub has one-click Files, Writer, Media, Photos, Snake and Terminal tiles; **F1** opens the full app grid. The taskbar can be placed left, bottom or top in Settings. The speaker opens a volume bubble; click its title to switch to brightness. **F3** opens Terminal; `exit` or **Esc** returns to the desktop hub. `Hide` keeps the app's contents. **Right-click** opens a context menu: on the desktop (Terminal, All Apps, wallpaper, About), on a window title bar (Maximize/Fullscreen/Hide), on a file (Open, Rename, Duplicate, Delete, Properties), and inside Writer, Sketch, Terminal, Media, Photos, Snake and Calculator. Clickable controls pulse briefly and major workspace changes use short fades; Fast graphics disables alpha-based transitions for performance.
* **Max** uses the work area without covering the dock. Drag a window by its title bar. **F11** (or Full) gives the app the entire framebuffer; press it again or click Restore. Layout is recomputed from native screen bounds. No scaled screenshot or fixed-size canvas stretched under the controls. Sketch rendering and framebuffer presentation were optimized; Settings → Graphics: Fast skips transparency blending for smoother repainting.
* **Files** starts with `welcome.txt`, `ideas.txt`, `example.mus`, and `pattern.pbm` on a fresh Home disk; select and Open or double-click. **Ctrl+N** creates a note. Files sorts (A–Z, Z–A, size), filters by typing (Search), renames inline, duplicates and deletes (two clicks to confirm), and shows each file's kind and size. Opening a file picks the app by extension: `.mus` → Media, `.pbm`/`.pgm`/`.ppm` → Photos, anything else → Writer. With more width, Files adds a preview, Writer shows a document rail, Calculator puts the result beside its keypad, and Settings splits into columns. Sketch uses normalized coordinates so drawings survive resizing; **Save .pbm** stores a 64×36 picture in Home for Photos.
* **Writer**: type, Enter, arrow keys, mouse caret placement, Home/End, Backspace/Delete, PgUp/PgDn. **Ctrl+S** saves, **Ctrl+A** selects all, **Ctrl+C/X/V** copy/cut/paste the selection (or whole document), **Ctrl+Z** undoes, **Ctrl+F** finds the next match, **Ctrl+R** reverts the draft to its session copy. The footer counts words, characters and lines. Switching apps does not discard a draft. Opening a different document with unsaved edits is blocked.
* **Calculator** supports signed 32-bit integer arithmetic, parentheses and precedence; overflow and division by zero report errors. Memory keys (MC/MR/M+/M-) and **Ctrl+C** copy the result. **Clock** reads the hardware clock, runs a countdown, shows a navigable month calendar when the window has room, and now includes a stopwatch. **Media** plays built-in tunes and your `.mus` files on the PC speaker with a visualizer and volume; **Photos** views built-in scenes and Netpbm pictures (Fit/Actual zoom); **Snake** is a keyboard-and-mouse arcade game with score and best. See [media formats](docs/media.md) — there is no MP3/MP4/WAV/JPEG support and no audio card. **Settings** controls software brightness, feedback pitch/silence, accent, wallpaper, left/bottom/top taskbar placement, auto-hide, whether new apps start maximized, and Fast/Fancy graphics plus a sound test. On narrow screens switch between Controls and Workspace; choose Save preferences to Home for persistence. Taskbar placement is appended to the Home snapshot format; older Home snapshots remain readable and migrate on the next save.
* **Terminal**: `help`, `apps`, `packages`, `run NAME [ARGS...]`, `install NAME`, `runfile PATH [ARGS...]` (UEFI app disk), `open NAME`, `ls`/`dir`, `cat FILE`/`type FILE`, `edit FILE`, `new FILE`, `save`, `rm FILE`, `mv OLD NEW`, `cp SRC DST`, `wc FILE`, `find TEXT`, `play FILE`, `view FILE`, `calc EXPR`, `echo TEXT`, `uptime`, `disks`, `lspci`/`drivers`, `install`, `ver`/`uname`, `clear`/`cls`, `exit`. **Tab** completes commands and filenames; **Up/Down** recall history. These are native commands, not a Windows/Linux command interpreter.

## Kernel and data boundaries

FreshOS 2's Stratus uses its own x86 kernel in `native/`; it does not use Linux kernel code. The earlier Linux 6.12.118 + Alpine ISO was a separate boot test, not integrated into Stratus, and is no longer part of this build. BIOS uses an El Torito loader and VBE; EFI negotiates GOP and exits firmware boot services. Stratus validates the display handoff, installs its own exception table, drives a 60 Hz PIT and polls a bounded PS/2 input queue. Kernel CPU faults halt with a framebuffer and COM1 report. On a detected VMware display it also negotiates the absolute-pointer protocol. `lspci` reads PCI IDs; listing a controller does not mean there is a driver for it. In particular, Stratus has no USB mass-storage driver today; Home and installation writes are limited to the marked ATA/IDE target. QEMU tests expose only virtual disks, not the user's physical USB devices. The desktop composites into its own buffer; pointer-only movement restores a small cursor region rather than repainting every app.

The installer verifies the copied system sectors from the ATAPI CD, preserves the separate Home area, and publishes the bootable MBR last. It refuses unmarked and already-installed targets. This is not an in-place upgrade tool; the compact ISO is for optical boot.

Home-2 accepts only its own marked ATA/IDE medium. A save writes an inactive snapshot, flushes, then publishes its generation and checksum. Boot verifies snapshots and selects the newest valid copy. Limit: 16 text documents, 3,071 ASCII bytes each. This is a small document store, not a general filesystem. Built-in desktop sessions share the kernel address space. On supported x64 UEFI machines, external x64 packages run at CPL3 with a separate page-table root.

**No Aero Browser or Chrome.** On x64 UEFI, supported 32- and 64-bit packages execute synchronously using the CPU. The legacy BIOS backend uses the bounded interpreter. Windows and Linux subsets, supported sample programs and missing services are documented in [IMP2 on Stratus](docs/imp.md). This is not a drop-in replacement for either OS.

## Build

On Linux with GCC, GNU binutils (including the `i386pep` linker emulation), DejaVu Sans and Python, install `requirements.txt`, then run `python forge/media.py all`. No host libc is linked into either kernel. Output: `distros/FreshOS-{Normal,Lite,VMware,VMware-Lite}.zip`. The `.sha256` checks the extracted ISO; the same digest is inside each ZIP. The compact optical images are under 10 MiB, not padded to 8 GB. Graphics are rasterized at build time; the guest depends on no host windowing system.

Compatibility limits and a staged plan for FreshOS-native Linux/Windows application support, USB ownership safety, and kernel testing are described in [the Stratus runtime roadmap](docs/native-runtime-roadmap.md). The native runtime currently supports only the bounded subsets documented there; it is not a universal Linux environment or a guarantee for every Windows application or installer.
