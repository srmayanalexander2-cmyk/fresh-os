# What is still missing from `take.txt`?

**Baseline:** native FreshOS 1.2, commit `5c4e611`. **Finding:** bootable media and a working native desktop were delivered; the full Windows replacement described in the transcript was not. In particular, approving an IMP document save is not the requested privilege system, and a disk-only boot test is not a Windows migration test.

Line numbers below refer to the attached `take.txt` (SHA-256 `edaac398b72193ebc7232d4fdb27a55bcd236f5abc91cd64d365085ac0620be3`). The file mixes user requests, old assistant replies and commands for a different HTML/Alpine project. This review compares requests with the current source, ZIP member sizes and [recorded release tests](verification.md); it is not a new hardware or boot certification.

## Older features described as already built

These were described in assistant replies, notably lines 257–271, 458, 580–620 and 744–749. They should not be counted as delivered merely because the transcript names files or reports passing tests.

- **Kernel and filesystem:** Today's built-in app sessions are not isolated preemptive processes. Fresh Home is a flat versioned record store, not the described permissioned directory tree with watchers, quotas, trash and recovery.
- **Desktop and shell:** Drag/minimize/restore exist. Eight-handle resizing, snapping/tiling, virtual desktops, Aero Peek, unified search, notification center, lock/sleep and desktop marquee selection are not the native shell described. The current terminal has editing, completion, history and scrollback, not the old piped/redirected 60-command shell.
- **Apps:** `kernel/shell.c` registers 13 built-in sessions, not the 32+ in old replies. Missing examples include a browser, persistent app Store, Photos, Music with visualizer, Weather, Security Center and Registry Editor. Writer, Paint, Calculator, Tasks and Minefield are smaller than the editor, layered painting, multi-mode calculator, process manager and games collection described there. See [coverage](coverage.md) for the separate Windows/removed-app wishlist.
- **Evidence:** The old JS/DOM test counts, Alpine build instructions and historical boot timings do not validate the custom kernel. Physical radio interoperability, VMware Workstation operation, universal PC compatibility and daily-driver reliability are not established by the native QEMU tests.

**Not omissions:** The IMP path was chosen instead of copying Windows code; Wine is explicitly excluded. The later removal of APK support stands. The old HTML kiosk and Alpine base are not dependencies to restore.

**Recommended order:** (1) establish the account/permission model and a directory filesystem, with denial and recovery tests; (2) build read-only Windows discovery and a copy-and-verify migration on disposable disk fixtures *before* considering any format operation; (3) exercise the app ABI against a named list of real applications and installers. Those milestones would make substantially stronger evidence for switching from Windows than another increase in ISO size.
